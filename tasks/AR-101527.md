# AR-101527 — DsFiltersBar: connect pieces together

Jira: https://drivenets.atlassian.net/browse/AR-101527 (epic AR-98410)
PR: https://github.com/drivenets/design-system/pull/775

## Goal

Ship `DsFiltersBar` as a public, full-featured **Component**. It is a single component that renders every part itself and owns the filter workflow state (ADR-0009), so a screen needs only data, persistence callbacks and counts. It comes with a **Row matcher** for client-side data (ADR-0010).

The first commit on the PR built and exported the compound API. This phase replaces that API before its first release.

## Acceptance criteria

### Single component

- `<DsFiltersBar fields value onValueChange />` with no children renders the disclosure. Collapsed, it shows the **Filter summary**. Expanded, it shows the toolbar in Figma order: saved filters, search, view switch, the active **Filter view**, save, clear all. The pinned row sits below in both states.
- `DsFiltersBar` is a component, not a namespace. `DsFiltersBar.Root`, `.Toolbar` and the other parts are not exported, and their stories are gone.
- `value` / `defaultValue` / `onValueChange` hold one **Filter document** `{ conditions, query }`. `conditions`, `query` and their callbacks are gone from the root.
- `slotProps.<part>` forwards `className`, `style`, `ref` and that part's own props to one part. Examples: `slotProps.search.ref` focuses the search input, and `slotProps.builder.suggestedFields` orders the builder's fields.
- `locale` is nested by part (`locale.search.placeholder`, `locale.savedFilters.saveFilter`, …). Every string a part showed before can still be overridden.

### Optional features

- `views={['filters', 'advanced']}` shows only those views. With one view, the view switch is hidden. A requested view that isn't listed falls back to the first listed one.
- Without `savedFilters`, the saved-filter picker and the save button do not render.

### Saved filters

- With `savedFilters`:
  - Choosing an item loads its `document` into the bar and reports it through `onValueChange`.
  - The picker shows the item's condition count, and shows it dirty once the document differs from the active item's.
  - The summary shows the active item's name.
- Save as calls `onSaveAs(name, document)`, and the returned id becomes the **Active saved filter**. Update calls `onUpdate(id, document)`. Rename and delete call `onRename` and `onDelete`. Deleting the active item drops the active selection.
- Every saved-filter callback may return a Promise, and the control that launched it stays loading until it settles.

### Pins

- Pins render as a pinned row built from `pins` and `fields`:
  - one group per field, in `fields` order, labeled with the field label
  - one toggle per pin, in `pins` order, labeled with the option or preset label
  - no row while there are no pins
- Turning a toggle on or off reports `onActiveTogglesChange` (`activeToggles` / `defaultActiveToggles`). Unpinning an option that is switched on also switches it off.
- `getPinCount(pin)` gives each toggle's count. Without it the toggles show no count and are never disabled for a zero count.

### Clear all and counts

- Clear all:
  - empties the document
  - switches every toggle off
  - drops the **Active saved filter**
  - keeps the **Pins**
  - leaves focus on the search input
- `resultCount` shows as the summary count.

### Row matcher

- `filterRows(rows, { fields, value, activeToggles, getValue?, resolveDatePreset? })` returns `{ rows, getPinCount }`. `useFilteredRows` is the same, memoized.
- It follows the rules in ADR-0010. It evaluates the conditions, or the parsed **Advanced query** while one is set.

### Kept from the first commit

- The view switch, its lock while an **Advanced query** is set, and the builder view's chips with the dialog opening only from "+" or a chip all behave as in the first commit.

### Exports and stories

- Exported from `@drivenets/design-system`:
  - `DsFiltersBar` and `DsFiltersBarProps`
  - `DsFilterDocument` and `emptyFilterDocument`
  - the field, condition and pin types, and the operator arrays
  - the nested locale type and `defaultDsFiltersBarLocale`
  - the `slotProps` and saved-filter types
  - `filterRows`, `useFilteredRows` and their types
  - `parseFilterQuery`, `serializeFilterQuery` and the query AST and result types
- Storybook `Components/FiltersBar` has:
  - **Default**, **With Table** and **Localized**. **With Table** uses `useFilteredRows`; there is no story-only matcher.
  - feature stories: **Collapsed**, **Search Only** (no `fields`), **Views**, **Advanced Query**, **Pinned**, **Saved Filters** and **Slot Props**
  - the internal building blocks, unchanged, under `Components/FiltersBar/Internal/*`

## Decisions

### API shape and public surface

- **Single component (ADR-0009).** The parts become internal components under `components/`, and the root composes them. No compound or "advanced layout" escape hatch ships now; exporting the parts later is additive.
- **Props layout:**
  - `slotProps` (repo convention: props for a part) carries per-part props.
  - `slots` (content replacement) is used only through a part's own props, such as `slotProps.query.slots.help`.
  - Strings go in a nested root `locale`, not in `slotProps`.
- Root props, in order:
  - config: `fields`, `value`/`defaultValue`, `pins`/`defaultPins`, `activeToggles`/`defaultActiveToggles`, `expanded`/`defaultExpanded`, `view`/`defaultView`, `views`, `savedFilters`, `resultCount`, `getPinCount`, `locale`, `slotProps`, `ref`, `className`, `style`
  - callbacks: `onValueChange`, `onPinsChange`, `onActiveTogglesChange`, `onExpandedChange`, `onViewChange`
- `savedFilters` is one object, `{ items, activeId?, defaultActiveId?, onActiveIdChange?, onSaveAs, onUpdate, onRename, onDelete }`:
  - Items are `{ id, name, document }`.
  - `onSaveAs` returns the new id, or a Promise of it.
  - The bar computes `count` and `dirty`. Dirty compares `query ?? serializeFilterQuery(conditions)` for the two documents.
- Active toggles stay outside the **Filter document**, as CONTEXT.md already says. Saved filters do not store them, and they never appear in the summary.
- `slotProps` keys:
  - `disclosure`, `summary`, `toolbar`, `savedFilters`, `saveFilter`, `viewSwitch`, `conditions`, `clearAll`, `pinned`
  - `search`: `value`, `defaultValue`, `onValueChange`, `disabled`
  - `builder`: `suggestedFields`
  - `query`: `disabled`, `slots`
  - Each part also takes `ref`, `className` and `style`.
- Search always renders. Hiding it is out of scope.
- Part prop types and per-part `defaultDsFiltersBar*Locale` exports leave the public surface. The nested locale type and its default replace them.

### Row matcher

- **Row matcher (ADR-0010):**
  - It lives in `ds-filters-bar/row-matcher/`.
  - Its rules are the story matcher's, made general: date presets go through `resolveDatePreset` instead of the story's fixed `today`/`last7Days`/`last30Days` table, and values are read with `getValue`, which defaults to `row[field]` or `row[field][subfield]`.
  - Today's `stories/common/match-rows.ts` becomes the implementation and the story file is deleted.

### Story and earlier decisions

- **With Table** stays a sibling above `DsTable` in a `DsStack`.
- The earlier locked decisions on the view switch, lock derivation, builder dialog, clear-all focus, Figma order and icons still hold.
- **Superseded:**
  - Row evaluation is no longer story-only (ADR-0010).
  - Saved filters no longer keep per-part, consumer-owned payloads.
  - Pins are no longer consumer-mapped.
  - The per-part story files are dropped, because the parts are internal.

### Phase 3 — lighter Field schema

- **Built-in operators.** `operators` is optional on every scalar field and takes plain values or the operator objects. Omitted means the type's full set, in the order of `enumFilterOperators`, `textFilterOperators` and `comparisonFilterOperators` (ADR-0006's fixed set).
- **Operator words by type.** `locale.operators.{text,enum,number,date}[op]` holds `{ label, symbol }`; `>` reads `greater than` on a number and `after` on a date. An operator object on a field wins over the locale, which wins over the defaults. `DsFilterOperator.label` becomes optional so an object can override just the symbol.
- **`locale.query.operators` stays.** It is the syntax reference's type-agnostic glossary (`IN` is "is one of" for every type), not the per-type labels, so it is not folded into `locale.operators`.
- **One resolution.** An internal, idempotent `resolveFields(fields, locale)` fills in operators and presets once in the root; every part reads the resolved fields from context. `parseFilterQuery` and `filterRows` resolve with the default words, so they accept the shorthand too. The filters dialog keeps a public-typed `tab.schema` and resolves it itself, so a dialog rendered alone still works.
- **Built-in date presets.** `dateFilterPresets` (`today` … `thisYear`) are listed on a date field by value and labeled from `locale.datePresets`; an object is a custom preset. The matcher asks `resolveDatePreset` first and falls back to the built-in rule in UTC calendar days from `now` (ADR-0010). A built-in value the field does not list is not a preset.
- **Document input.** `value`, `defaultValue`, a saved filter's `document` and the matcher's `value` take `DsFilterDocumentInput`: `query` and condition ids may be left out. `toFilterDocument` assigns `filter-condition-<index>` (suffixed on collision), so the same input always gets the same ids. A full document passes through by reference. Everything the bar reports is a full `DsFilterDocument`.

## Out of scope

- Exporting the parts, or any custom-layout API.
- A toolbar `actions` slot for extra buttons. Add one when a product asks.
- Hiding search.
- Server-side filtering helpers.
- Storing active toggles in **Saved filters**.
- Deprecating `DsTagFilter`.
