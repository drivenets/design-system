# Testing with JSDOM

Components render and respond to user events in JSDOM-based test runners (Vitest or Jest with `jsdom`). JSDOM lacks a
few browser APIs the components use, so add these stubs to your test setup file:

```typescript
// vitest.setup.ts or jest.setup.ts
window.matchMedia = (query: string) => ({
	matches: false,
	media: query,
	onchange: null,
	addEventListener: () => {},
	removeEventListener: () => {},
	addListener: () => {},
	removeListener: () => {},
	dispatchEvent: () => false,
});

globalThis.ResizeObserver = class {
	observe() {}
	unobserve() {}
	disconnect() {}
};

Element.prototype.scrollTo = () => {};
Element.prototype.scrollIntoView = () => {};
```

Without them:

- Components with responsive props (`DsButton`, `DsStack`, `DsGrid`, `DsDrawer`, `DsPanel` and anything built on
  them, such as `DsDatePicker` and `DsTable`) throw `window.matchMedia is not a function` on render.
- Opening `DsSelect`, `DsAutocomplete` or another positioned overlay throws `ResizeObserver is not defined`, and so do
  components that measure their content, such as `DsTable`.
- `DsSelect` never commits the chosen option, and `DsTimePicker` throws when it opens (`scrollTo`).
- `DsCommentThread` throws on render (`scrollIntoView`).

## Older JSDOM versions

Jest 29 and 30 ship jsdom 20 and 26.

- Before jsdom 30 there is no `CSS.escape`, so keyboard navigation in `DsAutocomplete` and `DsRadioGroup` throws
  `CSS is not defined`. `@testing-library/jest-dom` installs a polyfill; without it, install `css.escape` and import it
  in your setup file.
- Before jsdom 27, highlighted option text is split, so `DsAutocomplete` options are named "Ban ana" instead of
  "Banana". Query them by text, or use jsdom 27 or later.

## CSS imports in Jest

If a test imports `@drivenets/design-system/index.min.css`, map CSS files to a stub in Jest
(`moduleNameMapper: { '\\.css$': '<rootDir>/style-stub.js' }`). Vitest handles CSS imports on its own.

## Known limitations

- JSDOM does no layout. Elements have no size, so a `DsTable` with `virtualized` set renders no data rows. Leave
  `virtualized` off in tests that check rows.
- Truncation (tooltips on truncated text), overlay positioning and scroll behavior can't be asserted. Cover them in a
  real browser (for example Vitest browser mode or Playwright).
- The `matchMedia` stub never matches, so responsive props resolve to the `md` breakpoint. Return `matches: true` to
  test `lg`.
- The `DsSlider` thumb appears one tick after render, so find it with `findByRole('slider')`.
- `DsCodeInput` logs JSDOM's "Not implemented: HTMLCanvasElement's getContext()" message. It is harmless.

## Writing tests

Query components by role and accessible name (`getByRole('combobox')`, `getByRole('dialog', { name: 'Title' })`) and
drive them with `@testing-library/user-event`. The design system runs its own scenarios with exactly this setup in
[`tests/jsdom`](https://github.com/drivenets/design-system/tree/main/packages/design-system/tests/jsdom).
