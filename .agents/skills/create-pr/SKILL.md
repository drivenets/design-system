# Create PR

Owns the PR body, the screenshots, and the `gh pr create` call. Branch, commit and fork rules: [AGENTS.md#git--prs](../../../AGENTS.md#git--prs). Changeset wording: [AGENTS.md#comments--changesets](../../../AGENTS.md#comments--changesets).

## Step 1 — Gates (do not skip)

1. [pr-prep](../pr-prep/SKILL.md) report is all PASS (or each FAIL is reported to the user).
2. [code-review](../code-review/SKILL.md) has run on the full diff against `drivenets/main`.
3. Changeset exists, or the change is CI / docs / tests / tooling only → label `skip changelog`. Never skip for a bug fix.

## Step 2 — Screenshots

Required when the diff changes what renders: `*.tsx` (not tests), `*.module.scss`, `*.stories.tsx`, tokens. Skip for CI, docs, dependency bumps and test-only changes.

- **Before:** taken at the start of work (step 0 of [implement](../implement/SKILL.md), [fix](../fix/SKILL.md), [figma-to-component](../figma-to-component/SKILL.md)). Missing → capture from a worktree at the merge-base, not from the deployed Storybook.
- **After:** same story, state and viewport as before.
- **New component:** after only, plus the Figma link.

Capture, naming and hosting: [SCREENSHOTS.md](SCREENSHOTS.md).

## Step 3 — Title and body

Title = the PR's conventional commit subject, e.g. `fix(design-system): cap DsToast height at 400px [AR-1234]`.

Body — use this template, drop empty sections:

```markdown
{1–3 sentences: what changes for the consumer, and why.}

## Changes

- {behavior, not mechanism — at most 5 bullets}

## Screenshots

| Before                                                      | After                                                     |
| ----------------------------------------------------------- | --------------------------------------------------------- |
| <img src="{url}" width="420" alt="before, {what is wrong}"> | <img src="{url}" width="420" alt="after, {what changed}"> |

## Notes for reviewers

- {only trade-offs, risks, or follow-ups}
```

Keep it under ~1,500 characters. Never include: file lists, implementation walkthroughs, test lists, checker output, or "generated by" lines — CI and the diff already show those. The Jira key in the title links the ticket; no extra link needed.

## Step 4 — Open

```bash
git push -u origin HEAD
gh pr create -R drivenets/design-system --base main \
  --head "$(gh repo view "$(git remote get-url origin)" --json owner -q .owner.login):$(git branch --show-current)" \
  --title "{title}" --body-file {body.md} [--label "skip changelog"]
```

- Ready for review, not draft, unless the user asks.
- Other labels come from `labeler.yml` — don't add them by hand. Reviewers come from `CODEOWNERS`.
- PR already open for this branch → push and update the body; don't open a second one.

## Done when

- [ ] Gates passed or gaps reported
- [ ] Before/after table present when the diff changes what renders
- [ ] Body follows the template and length limit
- [ ] PR URL reported to the user
